**Visual design** lets you inspect the running page, edit layout and appearance in a Design sidebar, then **Apply** those changes to project source. It lives in the **Browser** tab, not in the code editor.

For Tailwind class panels on tokens in the file, see [Design Tools](/docs/editor/design-tools).

## Open the Browser

- Chrome icon at the bottom of the [activity bar](/docs/workspace/activity-bar)
- **View → Preview**
- Command palette: search for Preview

The tab is labeled **Browser**. It has back, forward, reload, a URL field, and an **Open externally** button.

Start your app from **Scripts** or the [terminal](/docs/terminal/integrated-terminal), then enter the local URL (often `http://localhost:3000`).

## Turn on design mode

Click the **palette** in the Browser toolbar, or press **Ctrl+Shift+D**. The Design sidebar opens on the right.

The **inspect** control (eyedropper) is on while you select elements. Click the page to target a node. The overlay shows the tag and a short label, for example `button.Get started`.

| Action | What it does |
| --- | --- |
| Click | Select the deepest control under the cursor (buttons/links preferred). Full-page layout shells are ignored |
| **Ctrl+click** | Add to the selection |
| **Shift-drag** | Select a region (marquee) |
| **Drag** (positioned) | Move by `left`/`top` with snap guides. `static` elements promote to `relative` at `0,0` (no jump). Hold **Alt** to force free-move instead of flex reorder |
| **Drag** (flex/grid child) | Reorder siblings inside an auto-layout parent (not under `body` / `#__next`) with an insertion line |
| **Resize handles** | Change width and height on the selection |
| **Double-click text** | Edit text content on the canvas (also available in the Typography panel) |
| **Arrow keys** | Nudge offsets (positioned) or sibling index (flex/grid). Shift = larger step |
| **Ctrl+I** | Toggle inspect vs interacting with the page |
| **Escape** | Clear the selection |

When inspect is off, you can click links and use the page as usual.

## Design sidebar

After you select an element, the sidebar shows:

| Section | What you edit |
| --- | --- |
| **Position** | X and Y offsets |
| **Layout** | Block, horizontal, vertical, or grid; width and height |
| **Appearance** | Radius (scrubbable input), padding, overflow |
| **Fill** | Background or text color, opacity |
| **Stroke** | Border width, style, and color |
| **Effects** | Shadows and similar |
| **Styles** | **Color tokens** (CSS variables ≈ Figma variables) and **Text styles** (composite size/weight/line-height ≈ Figma text styles). **+** opens a side flyout (color token or text style); defaults to `:root`, optional `@theme` utilities when the file already uses `@theme` |
| **Export** | Copy or export related assets |

Fill colors owned by `var(--token)` can **Edit token** (patch the shared variable) or **Detach** (write a plain color on the element).

If the selection comes from a React component, use **Apply to component** to retarget the write to the component root; leave it off to patch the instance element.

Changes preview live in the iframe. They are pending until you apply. Canvas moves, resizes, reorders, and text edits participate in the same undo stack as inspector changes.

## Apply to source

The footer shows how many pending edits you have.

1. **Undo** reverts the last design change in the preview.
2. **Apply** writes matching updates to JSX, HTML, or CSS in the open project.
3. **Reset** (toolbar) clears pending preview edits without writing files.

Apply needs an open project folder and a local preview it can map back to source. If a node cannot be located, the sidebar marks that element and leaves the rest applied.

**Ctrl+Z** / **Ctrl+Y** undo and redo design-mode history while the Browser tab is focused (outside text fields).

## Device frames

With design mode on, the device control frames the preview at phone and tablet sizes (iPhone, Pixel, iPad, and Full). Full uses the whole tab.

## Troubleshooting logs

When design mode misbehaves, check the **Shape** terminal (the one running `tauri:dev`), not the project app logs.

Look for blocks that start with `shape/design` and end with `end`. Copy that whole block into chat — it includes session id, event name, and structured context so the failure is diagnosable.
