**Visual design** opens the running website in a source-backed canvas. Select, move, resize,
duplicate, delete, or edit an element and Shape writes a deterministic source change — it does
not ask an AI model to rewrite the file.

Design mode supports:

- React projects running with Vite
- Next.js
- Astro
- Remix

Other project types are left unchanged.

For Tailwind class panels on tokens in the file, see [Design Tools](/docs/editor/design-tools).

## Open the Browser

- Chrome icon at the bottom of the [activity bar](/docs/workspace/activity-bar)
- **View → Preview**
- Command palette: search for Preview

The tab is labeled **Browser**. It has back, forward, reload, a URL field, and an **Open externally** button.

Start your app from **Scripts** or the [terminal](/docs/terminal/integrated-terminal), then enter the local URL (often `http://localhost:3000`).

## Turn on design mode

Click **Design** in the project sidebar, or press **Ctrl+Shift+D**. Shape discovers the project's
routes, connects to the local development server, and opens the full designer. The animated
canvas loader remains visible until the live page and source bridge are ready.

The **inspect** control (eyedropper) is on while you select elements. Click the page to target a node. The overlay shows the tag and a short label, for example `button.Get started`.

| Action | What it does |
| --- | --- |
| Click | Select the deepest control under the cursor (buttons/links preferred). Full-page layout shells are ignored |
| **Drag `•••`** | Move an element. Static elements are promoted to `position: relative` without changing their initial layout |
| **Resize handles** | Change width and height |
| **Double-click text** | Edit direct static text in place |
| **Arrow keys** | Nudge by 1px; Shift nudges by 10px |
| **Ctrl+D** | Duplicate the selected source element |
| **Delete** | Delete the selected source element |

When inspect is off, you can click links and use the page as usual.

## Designer panels

The left panel contains the live DOM layer tree, project routes, and source-backed assets. The
bottom toolbar contains selection, undo/redo, capture, code, responsive frame, and zoom
controls. There is no separate left activity toolbar.

After you select an element, the sidebar shows:

| Section | What you edit |
| --- | --- |
| **Position** | X and Y offsets |
| **Layout** | Block, horizontal, vertical, or grid; width and height |
| **Spacing and size** | Per-side margin and padding, gap, min/max constraints, width and height |
| **Fill** | Background or text color, opacity |
| **Stroke** | Border width, style, and color |
| **Effects** | Shadows, filters, backdrop filters, transforms, opacity, blend mode |
| **Motion** | Transition property, duration, easing, transform, and transform origin |
| **Settings** | Source tag, ID, classes, attributes, and accessibility metadata |

Changes preview immediately in the iframe and are then committed through the source engine.
The engine resolves the DOM element to a JSX or Astro source range, applies only the selected
attribute or node operation, parses the result, and rejects the edit if the match is ambiguous,
the expression is dynamic, or syntax would regress.

## Source safety

- Source files remain the single source of truth.
- No AI is used to apply visual edits.
- Existing dynamic `style` expressions are never overwritten.
- Direct text editing refuses nested or expression-generated content.
- Every edit is syntax checked before writing.
- Undo and redo restore exact file snapshots.
- If more than one source node is an equally strong match, Shape asks for a more specific
  selection instead of guessing.

## Device frames

Use the bottom toolbar to switch between full, tablet (768px), and mobile (390px) frames and to
change canvas zoom.

## Deploy

The **Deploy** menu previews supported destinations with their official marks, including Vercel,
Netlify, Cloudflare Pages, Railway, Render, Fly.io, AWS Amplify, Firebase, GitHub Pages, and
Framer. Provider connections are intentionally disabled for now.

## Troubleshooting logs

When design mode misbehaves, check the **Shape** terminal (the one running `tauri:dev`), not the project app logs.

Look for blocks that start with `shape/design` and end with `end`. Copy that whole block into chat — it includes session id, event name, and structured context so the failure is diagnosable.
